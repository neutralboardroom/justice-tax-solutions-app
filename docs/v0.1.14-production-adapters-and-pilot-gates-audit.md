# Justice Tax Solutions v0.1.14 — production adapters and pilot-stage gates

## Purpose

This pass moves the platform one step closer to a safe controlled pilot without weakening the core rule that real sensitive taxpayer document handling must stay blocked until production gates are intentionally configured.

## What changed

- Current-version references were updated to v0.1.14 across package metadata, runtime storage summary, static smoke tests, brand/launch/customer-experience modules, README, and current API messaging.
- Production configuration now reports database adapter readiness, including local JSON development mode versus the managed PostgreSQL production path.
- The production page now shows database, storage adapter, malware quarantine, transactional email, staff/MFA, Render deployment, and pilot-stage blockers in one view.
- Storage provider readiness now includes a clearer adapter contract for private object storage, signed downloads, retention, and access logging.
- Malware scanning now has a quarantine workflow, clean-release gate, and unsafe-file response plan.
- Staff/professional approval and MFA planning are surfaced as production blockers before live sensitive taxpayer document handling.
- Pilot-stage gates now separate internal demo, private pilot without sensitive uploads, controlled paid pilot, and public live launch.

## Preserved

- Referral QR/flyer tools and referral reward ledger.
- Official IRS/NYS/NYC form ZIP ingestion readiness and form-mapping queue.
- Sensitive-upload blocking by default.
- Redacted/sample upload acknowledgment for private demos and testing.
- Professional review workflow, PTIN/CPA/EA/tax-attorney credential tracking, compliance checklist, client approval, and release gates.
- Multi-AI vendor fallback architecture.
- Stripe checkout/webhook foundation and mock/test payment paths.
- Customer-facing Justice Tax Solutions brand and tax-problem-first positioning.

## Remaining blockers before live sensitive taxpayer documents

- Managed PostgreSQL must be configured, migrated, backed up, and tested.
- Private object storage must be configured and permission-gated.
- Malware scanning must be integrated before staff previews or downloads live uploads.
- Transactional email must be configured with authenticated sending domain.
- Stripe live checkout and webhook must be configured if paid release is enabled.
- Staff/professional approval and MFA or equivalent access control must be operational.
- At least one qualified professional reviewer must be verified.
- Official form mappings must be verified before any form output is treated as client-facing final work.
- Written operating procedures/WISP must be completed before public launch.
