# Justice Tax Solutions v0.1.3 Production Foundation Audit

## Goal

This build moves Justice Tax Solutions closer to a live production tax-help platform while preserving the original strategy: tax problems and concerns first, with tax return preparation/review included.

## Added in v0.1.3

### Storage and database readiness

- Added `db/postgres-schema.sql` for the initial Render PostgreSQL schema.
- Expanded local JSON collections to match production concepts: password reset tokens, email verification tokens, staff invites, compliance checklists, client approvals, and document share tokens.
- Updated `/api/platform/production-readiness` and `/health` so deployment gaps are visible.

### Secure document handling foundation

- Uploaded files are now encrypted at rest using AES-256-GCM in the local starter adapter.
- Document downloads decrypt only after account/case permission checks.
- Document download access is logged without exposing storage paths.
- `.env.example` now includes `DOCUMENT_ENCRYPTION_KEY` and object-storage placeholders.

Production note: encrypted local storage is better than plain storage, but live tax documents should still use managed private object storage, malware scanning, retention rules, and least-privilege access.

### Stripe payment foundation

- Added Stripe dependency and `POST /api/payments/create-checkout-session`.
- Added `POST /api/payments/stripe/webhook` before the JSON parser so Stripe signature verification can use the raw body.
- Payment completion updates the case, stores the payment, and triggers the existing referral reward ledger.
- If Stripe is not configured, the payment request is still recorded and returned as not configured.

### Account recovery and email verification

- Added password-reset request and reset endpoints.
- Added email-verification request and verify endpoints.
- Development mode returns tokens for testing; production should deliver links through SMTP, Resend, SendGrid, or another email provider.

### Stronger roles and permissions

- Added `src/permissions.js`.
- Public user responses now include role permissions.
- Staff access respects active/pending status when `REQUIRE_STAFF_APPROVAL=true`.
- Added staff invite and admin role-update foundations.

### Professional compliance workflow

- Added `src/compliance.js` with PTIN preparer, accountant, CPA, EA, tax attorney, and human tax specialist requirements.
- Professional records now support PTIN last four, PTIN status, NYTPRIN/NY preparer status, license jurisdiction/number, EA number, identity verification, background review status, engagement scope, and compliance score.
- Added staff professional verification endpoint.
- Added case compliance checklist endpoints.
- Added client final approval endpoint.
- Release-to-client is now blocked by a release gate unless staff explicitly overrides it.

## Key release gate checks

A case should not be released as final client output until the platform has recorded:

- Client identity/contact confirmation.
- Tax years and agencies.
- Missing-document checklist review.
- Scope disclosure.
- No-guarantee acknowledgement.
- PTIN/professional requirement check.
- NY preparer registration/NYTPRIN check where applicable.
- Client approval.
- Payment verification.
- Assigned professional readiness.

## Still not complete for live production

Before using the platform with real customers and sensitive tax documents, the next passes should add:

- Full PostgreSQL adapter instead of local JSON active storage.
- Managed private object storage integration.
- Malware scanning and document retention/deletion policy.
- Real email delivery for verification/reset/staff invites.
- Full Stripe live-mode test, webhook replay handling, refunds/chargebacks, and customer portal.
- Staff/professional invitation acceptance flow.
- More granular per-case permissions for assigned professionals.
- EFIN/e-file provider or professional software/partner workflow.
- Return-preparer signature/consent and Form 8879-style e-file authorization workflow where applicable.
- Full professional engagement-letter workflow.

## Build status

This is a strong foundation for GitHub + Render deployment testing. It is not yet the final live tax-document production release.
