# v0.1.13 Production Configuration Layer Audit

This pass focused on moving Justice Tax Solutions from a feature-rich prototype toward a controlled private-pilot/live-readiness architecture.

## Main improvement

v0.1.13 adds a production configuration layer that explicitly separates:

- internal demo use
- private pilot with redacted/sample uploads
- controlled paid pilot
- future public live launch with real taxpayer documents

## Added controls

- `/api/platform/production-config`
- `/api/platform/sensitive-upload-policy`
- `/api/platform/storage-adapters`
- `/api/platform/malware-scan-policy`
- `/api/platform/transactional-email-templates`
- `/api/platform/render-deployment-checklist`
- `/api/staff/production-config-events`
- `/production-config.html`

## Upload gate

The intake now blocks sensitive-document uploads unless live upload configuration is intentionally enabled. During demo/private-pilot mode, users may only upload redacted/sample documents if they acknowledge the sample-document rule.

This prevents a common launch mistake: deploying a promising tax platform and accidentally inviting real W-2s, tax notices, SSNs, bank details, or prior returns before production storage and malware scanning are in place.

## Storage plan

The app still keeps encrypted local document storage for development/testing, but the production configuration layer now documents and checks the intended future adapter choices:

- encrypted local storage: demo/testing only
- S3 private bucket
- Cloudflare R2 private bucket
- Google Cloud Storage private bucket

## Malware scanning

v0.1.13 adds scan-event recording and malware-scan provider planning. The scanner is still a provider hook/placeholder, not a full scanner integration. Live sensitive uploads remain blocked unless scanner configuration is enabled.

## Email templates

The release adds a transactional email template inventory for account verification, password reset, case started, document reminders, review requested, review released, urgent staff alert, and referral events.

Emails should never include sensitive taxpayer details in subjects or bodies; they should direct clients to sign in.

## Remaining blockers before live taxpayer documents

- real PostgreSQL adapter/migration execution
- private object storage implementation
- real malware-scanning adapter
- live Stripe checkout and webhook confirmation
- transactional email provider with SPF/DKIM/DMARC
- staff/professional MFA and approval workflow
- verified professional roster
- official form mapping and sample-fill QA
- written security plan completed and reviewed

## Result

v0.1.13 is safer for GitHub + Render testing and private pilot planning. It is not yet a public live tax-document platform.
