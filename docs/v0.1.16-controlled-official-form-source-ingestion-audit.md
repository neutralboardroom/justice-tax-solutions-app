# v0.1.16 Controlled Official Form Source Ingestion Audit

## Purpose

This version starts official IRS/NYS/NYC form ingestion and mapping without jumping straight to unsafe final PDF output. The new approach is source-first: identify and validate official government source URLs, seed a controlled source catalog, then capture PDFs, extract fields, draft mappings, sample-test, and require staff/professional verification before any client-facing completed form output.

## Added

- Official government source catalog for first IRS, NYS, and NYC waves.
- Source seeding endpoint for IRS/NYS/NYC official sources.
- Manual official source URL registration endpoint.
- Source URL validation against allowed official domains.
- Source inventory endpoint separating source-only records from captured PDF records.
- Controlled mapping plan endpoint with staged gates.
- Download-vs-upload guidance explaining that public government sources can be used for discovery, while captured PDFs are still required for field extraction and sample PDF testing.
- Source-driven mapping drafts with form-specific intake groups, document candidates, calculation checks, conditional sections, and QA requirements.
- Official Forms UI updates for source seeding, source registration, inventory, controlled stages, and existing ZIP upload.

## Safety Gates Preserved

- No form source is client-output-ready when it is only seeded or registered.
- Uploaded PDFs remain blocked from client output until verified.
- Source URL validity does not equal field mapping validity.
- PDF field extraction, sample-fill QA, calculation checks, signatures/preparer areas, and professional verification are still required before release.
- Existing sensitive-upload, production-readiness, referral, professional review, payment/release, and staff workflow foundations were preserved.

## Production Readiness

This version improves source readiness only. It does not remove the broader production blockers for live sensitive taxpayer document handling: managed PostgreSQL, private object storage, malware scanning, authenticated transactional email, live Stripe/webhook testing, staff/professional MFA or equivalent controls, verified professional reviewers, official form mapping QA, WISP/Publication 4557-style safeguards, and final operating procedures.
